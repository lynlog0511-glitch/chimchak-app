# 침착 (ChimChak)

> 돌봄받는 사람이 아니라 **돌보는 사람**을 훈련시키는 AI 시뮬레이터.
> AI는 어르신 역만 맡고, 옳고 그름의 판정은 한국 법령·공단 지침이 합니다.

2026 제8회 K-디지털 트레이닝 해커톤 · 팀 침착(ChimChak) 데모 웹앱.

## 핵심 기능 (MVP 3)

| 모드 | 내용 |
|---|---|
| ① 배우고 · 훈련 | AI 상황 시뮬레이터 — 시나리오 6종(현직 감수 완료 3종 + 감수 대기 3종) 실동작. 턴별 즉시 채점 + 법령·지침 근거 칩, 초조도 게이지, ⚑CF 즉시 인터럽트(무벌점 재시도) |
| ② 일하고 · 실전 | 핸즈프리 응급 음성 가이드 5종 — L3 구간은 생성 호출 0%, 사전 검수 고정 문구만 재생. PWA 오프라인 캐시로 서버가 죽어도 동작 |
| ③ 성장하고 · 기록 | 음성 보고 → 2단 가명처리 → 급여제공기록지 5요소 초안 → 사용자 확정. 훈련 이력은 점수 없이 충족/코칭 표시로만 누적 |

## 실행

```bash
npm install
npm run dev        # 개발: http://localhost:3000
```

**시연·오프라인 데모는 반드시 프로덕션 빌드로** (서비스워커는 프로덕션에서만 등록됩니다):

```bash
npm run build && npm start
npm run verify      # 게이트 4종: 타입 · 회귀 테스트 · 오디오 매니페스트 적중률 · 린트
npm run lint        # 린트만 따로 (훅 생명주기·접근성 — 규칙과 사유는 eslint.config.mjs)
```

주의: 빌드 전에 떠 있는 dev 서버(포트 3000)를 먼저 종료하세요. dev 서버가 `.next`를 공유하며 프로덕션 산출물을 오염시킵니다.

## 구조

```
src/
  data/        시나리오·루브릭 30항목·응급 프로토콜 — 코드가 아니라 데이터
  engine/      세션 상태 머신 · 규칙 판정(결정론) · 채점 · 가명처리 — React 무의존 순수 함수
  lib/         Web Speech(STT/TTS) 래퍼 · localStorage
  components/  공유 디자인 시스템 (코어 콘텐츠 17px+ · 48px+ 터치 타겟)
  app/         / /train /emergency /report /history /history/certificate /safety /for-orgs /check
public/
  audio/       사전 합성한 대사·응급 음성 + manifest.json (런타임 합성 0건)
  fonts/       서브셋 폰트 (외부 CDN 없음)
```

- 라우트 두 개는 성격이 다릅니다: `/for-orgs`는 기관 담당자용 한 장 안내, `/check`는 **발표자 전용** 무대 직전 점검 화면입니다(하단 탭바에 링크가 없고 noindex이며, 심사 화면이 아닙니다).
- 이 문서는 규칙 엔진 경계 케이스나 분기 수 같은 **시점 고정 수치를 적지 않습니다** — 커밋된 경계 케이스는 `/check`가 그 자리에서 라이브로 세어 보여 줍니다(「다시 검사」를 누르면 다시 돌아갑니다). 시나리오·프로토콜 종수도 화면이 데이터에서 세어 옵니다.
- **기본 배포는 외부 API 호출 0건** — 데모는 네트워크 없이 완주됩니다(대사 음성도 사전 합성분이고 폰트도 서브셋을 직접 실어 CDN이 없습니다). 상류를 부르는 자리는 온라인 모드를 켠 배포의 `/api/coach` 하나뿐이고, 서버 환경변수가 없으면 그 자리도 잠긴 채입니다. **판정 자리는 어느 배포에서든 비어 있습니다** — 채점은 결정론 어댑터가 그대로 맡고, 온라인 모드가 받아 오는 문장도 기기 안 가드 체인을 지나야 화면에 닿습니다.
- 시나리오 원본 명세: 팀 내부 문서 「침착 알파 시나리오 스크립트 & 평가 루브릭 설계서 v1.0」(CHK-DES-2026-001).

## 의존성 취약점에 대한 판단 (2026-08-06)

`npm audit`은 high 3건(next · postcss · sharp)을 알리고 critical·moderate·low는 0건입니다. **지금은 올리지 않는 것이 판단이며, 그 근거를 여기 남깁니다.**

- **패치 경로가 없습니다.** 세 건 모두 `fixAvailable`이 next 16 메이저이고, 설치된 next 15.5.22가 이미 15.x 최신입니다 — `npm audit fix`로 닫히지 않습니다.
- **문제의 경로를 이 앱이 쓰지 않습니다.** sharp/libvips는 이미지 최적화 경로인데 `next/image` 참조 0건(이미지 자산은 `public/icon.svg`와 PWA 아이콘 PNG 2장뿐이고, 전부 정적으로 그대로 나갑니다 — 8/23 현행화), postcss 권고는 빌드타임 CSS stringify이고 컴파일 대상은 저장소 안의 신뢰된 입력뿐입니다. 서버로 나가는 코드 경로는 **route handler 하나(`/api/coach`)뿐이고 server action은 0건**인데, 그 경로는 위 두 권고가 가리키는 이미지 최적화·CSS 파이프라인과 닿지 않습니다(온라인 모드의 상류 중계 하나이며, 환경변수가 없는 배포에서는 그 자리도 잠깁니다). 그 라우트 자신의 방어는 별도로 다섯 겹입니다 — 출처 확인 · 표식 대조와 갱신 · IP당·배포당 한도 · 입력 검증(모양·길이·보이지 않는 글자) · 무로그 중계(`src/app/api/coach/route.ts` 머리 주석).
- **파일럿 전환 시 별도 작업으로 잡습니다.** next 16 업그레이드는 App Router 동작 변경을 동반하므로 발표 전에는 손대지 않고, 전환 준비 기간에 회귀 검사와 함께 진행합니다.

> **이 판단이 한동안 틀린 근거 위에 서 있었습니다 (8/27 교정).** 위 둘째 줄은 8/6에 「route handler·server action도 0건이라 서버로 나가는 코드 경로 자체가 없습니다」라고 적혔고, 8/24에 `/api/coach`가 생기면서 그 전제가 거짓이 되었는데도 3일간 그대로 남아 있었습니다. **결론(지금은 올리지 않는다)은 바뀌지 않습니다** — 권고 셋이 가리키는 경로를 그 라우트가 쓰지 않기 때문입니다. 바뀐 것은 근거를 적는 방식입니다: 앞으로 이 절은 「0건」처럼 **코드가 늘면 조용히 거짓이 되는 문장**을 근거로 쓰지 않고, 어떤 경로가 몇 개 있고 그것이 권고와 어디서 갈리는지를 적습니다. 보안 판단의 전제는 코드가 바뀔 때 함께 갱신되지 않으면 판단 자체보다 오래 남습니다.
