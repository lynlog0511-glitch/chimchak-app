## 0. 한 줄 원칙

흰 지면 + 헤어라인 + 조용한 회색 면. **틸은 화면당 2곳 이하**(주 CTA/마이크, 활성 표시). 배지·칩·이모지·장식 아이콘 대신 **문장과 타이포**로 말한다. 빨강은 119와 ⚑CF에만, 앰버는 "다시 볼 것"과 감정 상태에만.

## 1. 컬러 토큰 (globals.css @theme 교체값)

기존 토큰명 유지, 값만 갱신. 새 토큰은 ★ 표시.

```css
/* 지면·면 */
--color-paper: #ffffff;        /* 본지면: 흰색으로 변경 (기존 #fafaf9) */
--color-paper-2: #f5f6f6;      /* 회색 면: 카드·입력 필드·보조 블록 */
--color-line: #eef0ef;         /* 헤어라인 (기존보다 옅게) */
--color-line-strong: #e4e7e5;  /* 아웃라인 버튼·입력 보더 */

/* 잉크 */
--color-ink: #191f1e;
--color-ink-soft: #454f4c;
--color-ink-muted: #5a625f;    /* 메타·라벨 — 6.27:1 (8/6 교정: AA 미달 37건 일괄 해소, PROJECT_BRIEF §4) */
--color-ink-faint: #69716e;    /* ★ 지문·캡션 — 5.01:1 */
--color-ink-disabled: #9aa5a2; /* ★ 비활성 전용 — 읽어야 하는 고지에는 ink-muted 사용 (8/6 교정) */
--color-ink-ghost: #8a918e;    /* ★ 셰브론·도형 장식 */

/* 브랜드 틸 — 스케일 유지, 역할 고정 */
--color-brand-600: #17948a;    /* 채움: 주 CTA·마이크·진행바·활성 세그먼트 */
--color-brand-700: #157f75;    /* 흰 지면 위 텍스트 링크 · 흰 글자 얹는 채움 — §9-8의 지면 조건 참조 */
--color-brand-800: #14665f;    /* 강조 텍스트·활성 탭·워드마크 · **색 면 위 글자는 전부 이 단** */
--color-brand-tint: #e7f4f2;   /* ★ 학습자 말풍선·마이크 링·틸 면 (brand-100 대체) */
--color-brand-on-tint: #0f3f3a;/* ★ 틸 면 위 텍스트 — 딥 텍스트의 정본 이름 (brand-900 대체) */
--color-brand-press: #0f3f3a;  /* brand-800의 눌림 단 — 링크 hover·채움 버튼 active (8/27 신설) */

/* 상태 */
--color-ok: #1e9e6a;  --color-ok-ink: #14764f;  --color-ok-soft: #eaf7f1;
--color-warn-ink: #b45309;  --color-warn-soft: #fdf1e5;
--color-warn-line: #f0c987; /* 앰버 선 · 아바타 감정 링(불안) — 8/26에 별칭 `emotion-ring` 폐기 */
--color-danger: #d64545;  --color-danger-ink: #b03636;  --color-danger-soft: #fdeeed;
```

- 8/26 정리: `--color-emotion-ring`을 지웠다. `warn-line`과 **같은 hex**(#f0c987)에 붙은 역할 별칭인데 참조가 0건이었다 — 「한 값에 이름 하나」(§9-8)가 「토큰 이름은 지우지 않는다」보다 앞선다. 감정 링(불안)은 `warn-line` 한 이름으로 적는다. 같은 날 참조 0건이던 `brand-300`·`brand-500`·`mint-50`도 함께 지웠다(§9-9).
- 8/27 정리: `--color-brand-900`을 지웠다. #0f3f3a에 이름이 둘이었고(`brand-900`·`brand-on-tint`) 정의 주석이 스스로 「(= brand-900)」이라 적고 있었다 — `white`를 별칭으로 승격시킨 것과 **같은 자리**이고, 흰색이 게이트로 닫힌 뒤 「한 값에 이름 하나」를 어기는 마지막 자리였다. 다만 그 이름이 하던 일이 둘이라 갈랐다: 「틸 면 위 딥 텍스트」는 정본 `brand-on-tint`로 옮기고, 「brand-800의 눌림 단」(링크 hover 둘 · 채움 버튼 `active:` 둘)은 값이 같아도 **가리키는 것이 달라** 역할 이름 `--color-brand-press`로 다시 세웠다. 게이트 ⑧의 별칭 목록에 `brand-900`을 더했다. 같은 날 `brand-200`·`ok-line`도 지웠다 — 등장은 각 1건이었지만 그 1건이 `Card.tsx` 보더 표의 한 행이고 그 행을 고르는 호출자가 0이라 **화면에 닿을 수 없는** 규격이었다(§9-9의 판정을 「참조 0」에서 「도달 0」으로 한 칸 올린 자리다).

사용 규칙:
- 색 면(brand-tint/ok-soft/warn-soft/danger-soft)은 화면당 1~2블록.
- 그라데이션 전면 금지 (게이지 포함 — 게이지는 단색 세그먼트).
- 학습자 말풍선은 brand-tint + on-tint 텍스트. **틸 채움 말풍선 금지** (채움은 CTA·마이크 전용).

## 3. 형태 언어

- radius: 말풍선 18px(화자 쪽 모서리만 4px — 인물은 좌상, 학습자는 우상), 카드·버튼 14px, 보조 12px, ~~입력바 24px(pill)~~ **입력 pill은 `--radius-chip`(999px) — §9-10**, 바텀시트 22px, 마커 사각 12px.
  - 토큰이 있는 값은 **토큰 클래스로만** 적는다: `rounded-card`(14) · `rounded-panel`(16) · `rounded-field`(12) · `rounded-chip`(999) · `rounded-full`(원형 도형 전용). 말풍선 18px은 네 모서리가 서로 다른 값이라 단일 토큰으로 적을 수 없어 복합 리터럴로 쓰고, 그 여섯 자리는 게이트 ⑤의 허용 목록에 사유·개수까지 등재돼 있다(2026-08-26에 `--radius-bubble` 토큰은 사용 0건으로 지웠다 — §9-9).
- 그림자: 기본 없음. 허용 3곳 — 바텀시트 `0 -10px 40px rgba(25,31,30,.25)`, 데스크톱 미리보기 카드 `0 8px 30px rgba(25,31,30,.06)`, 마이크 링은 그림자 아닌 `box-shadow: 0 0 0 3px var(--color-brand-tint)`.
- 보더: 헤어라인(line)은 리스트 행·섹션 구분 전용. 아웃라인 버튼·제안 버튼만 line-strong 1px. 카드는 무보더(paper-2 면) 또는 line 1px 중 택1 — 같은 화면에서 혼용 금지.
- ~~아이콘: 이모지 0건. **문자 기호만** — ‹(뒤로) › (이동) ⌄(펼침) ✓(충족, 15~17px 원형 배지 안) ↺(재훈련).~~ **폐기 — §9-12가 대체** (이모지 0건은 그대로 유효하고, 「문자 기호만」이 폐기된 부분이다: 하단 탭바는 2026-08-25부터 SVG 아이콘 5종 + 라벨이다.) 마이크는 CSS 도형(캡슐+받침), 파형은 2.5~3px 세로 막대 3~5개.
- 상태 표시: 🟢/⚪ 이모지 → **✓ 원형 배지(ok) / · 앰버 텍스트**로 전환. ⚑CF는 빨강 10px 점 + 문장.

## 4. 컴포넌트 스펙

### 4.1 세션 헤더 (모든 훈련 화면)
`‹ + [제목 16/700 + 부제 12.5 muted "N째 상황 · 대화 단계 · AI는 어르신 역만 맡습니다"] + 우측 "종료"`. 부제 앞 6px 틸 점 = 현재 계층 표시(L3 진입 시 danger 점 + "응급 단계 — 생성 0건"). 탭바는 세션 중 숨김.

### 4.2 세그먼트 진행바
CUE 수만큼 flex 균등 3px 막대, gap 3px, 완료=brand-600 / 남음=line. 응급 재생기는 danger / danger-soft. 진행률이지 점수가 아니므로 §3-1 위반 아님.

### 4.3 말풍선
- 인물: 아바타 38px 원(성씨 1자, paper-2 바탕) + **감정 링** `box-shadow 0 0 0 2px`(평온=투명, 불안=warn-line, 격앙=warn). 이름 줄: `박 어르신 · 조금 불안(warn-ink) · AI 가상 인물(ghost)`. TTS 재생 중이면 이름 줄 끝에 파형 3막대 + "읽어 주는 중"(11px brand-700). 본문 paper-2, radius 4/18/18/18. 아래 11px ghost 타임스탬프 "방금".
- 학습자: brand-tint 면 + on-tint 텍스트, radius 18/4/18/18, 우측 정렬, max-width 80%.
- 지문(무대 설명): 말풍선 아님 — 가운데 정렬 12.5px ink-faint 한 줄.

### 4.4 코칭 행 (FeedbackCard 대체)
박스 없음. `[✓ 17px 원형 ok 배지] + [라벨 줄: "충족 · 침착의 코칭"(12.5/700 ok-ink) + 델타 칩 "초조도 한 칸 ↓"(11.5 ok-soft 면)] + [본문 15px ink-soft] + [출처 줄 12.5 muted: 문서명 · 밑줄 "왜 이 판정인가요?"]`. 코칭(미충족)은 배지 대신 앰버 ·, 라벨 warn-ink. "왜 이 판정인가요?" 펼침에 판정 경로(규칙 id/분기 패턴/버튼)와 루브릭 행동지표 문장 — 점수·앵커 숫자는 비표시.

### 4.5 컴포저 (CueResponder)
상단 헤어라인. `[CUE 질문 17/700 + 우측 "여유 N초"(12px disabled, tabular)]` → 제안 버튼 목록(48px+, 흰 바탕, line-strong 1px, radius 14, 좌정렬 15px/500) → `[입력바(48px pill, paper-2, placeholder "직접 입력…") + 마이크 원 52px brand-600 + tint 링]`. 재촉 어휘 금지 — "남은 시간" 대신 "여유".
녹음 중(4b): 로그 영역 opacity .45, paper-2 면 카드에 `[빨강 8px 점 + "듣고 있어요" + 파형] + 실시간 자막 16.5px + 캐럿`, 마이크는 brand-800 + 이중 링, 아래 "손을 떼면 전송돼요 / 잘못 들렸다면 보내기 전에 고칠 수 있어요".

### 4.6 ⚑CF 바텀시트 (CriticalInterrupt)
전면 딤 `rgba(25,31,30,.32)` + 흰 시트 22px. `[빨강 10px 점 + "잠깐, 여기서 멈춥니다" 19/800]` + 이유 15.5px + 근거 박스(paper-2, 13px, **"판정: 규칙 사전 CO-01 (AI 아님)"** 명시) + "대신 이렇게 말해볼 수 있어요" 라벨 + 대안 3버튼(제안 버튼과 동일 스펙) + 주 CTA "같은 장면에서 다시 해보기 — 벌점 없음". 좌측 액센트 바·빨강 헤더 밴드 금지.

### 4.7 엔딩 (EndingPanel)
- 충족(6a): ✓ 54px ok 원 + eyebrow + 제목 22/800 "말이 먼저 나왔습니다" + 소요시간. "잘한 것 N"(ok-ink 라벨) 헤어라인 리스트(3개 + "외 N개 ⌄") → "다시 볼 것 N"(warn-ink) → CTA: 주 "다음 상황으로 — {다음 시나리오}"(56px) / 보조 2분할 "이 훈련 보고 연습 · 기록 보기" / 각주 "점수가 아닙니다 — 다음에 볼 지점 안내예요".

1. **주 CTA 채움 = brand-700** (§1은 brand-600으로 적어 두었으나 CTA에는 쓰지 않는다). brand-600(#17948a) 위 흰 글자는 대비 3.72:1로 AA(4.5:1) 미달이라 17px 이상 CTA 라벨에 못 쓴다 — brand-700(#157f75)은 4.86:1로 통과한다. brand-600은 마이크·진행바·상태 점처럼 "누르지 않는 표시"에만 남긴다. 근거: `src/components/BigButton.tsx` 24~36행.

3. **컴포저 내부 스크롤 — 재확인**: 모바일은 페이지 스크롤 하나이고 컴포저 도크는 그 안에 붙박이로 선다(§5 "내부 스크롤 박스 제거"는 그대로 유효) — 도크 전체가 페이지와 별개인 스크롤 박스가 되는 것은 여전히 금지다. 단 도크 가운데 켜(제안 버튼·입력창)만 상한(dvh)을 넘는 만큼 좁게 `overflow-y-auto`로 스크롤하고, 위 켜(CUE 질문)와 아래 켜(마이크·직접 입력)는 상한과 무관하게 항상 보인다 — 이 좁은 예외가 없으면 글자 크기를 키웠을 때 마이크 버튼이 화면 밖으로 밀려난다. 근거: `CueResponder.tsx` 110~124·623~635행.

    - **거부 목록은 두지 않는다.** 「아는 값을 막는」 형태는 아직 모르는 값을 통과시킨다 — 사다리 게이트가 거부 목록이던 동안 18px·28px이 그대로 지나갔고, 반지름 게이트는 12·14px만 세느라 16·18px을 놓쳤으며, 행간 게이트는 아홉 값을 이름으로 거부하느라 `leading-[1.15]`·`leading-[2]`를 놓쳤다. 2026-08-26에 **마지막 거부 목록 둘(반지름·행간 임의값)까지 허용 목록으로 뒤집었다**(5차 페르소나 디자이너 P2). 그때 이 자리는 「지금 이 파일의 열다섯 검사 중 모르는 값이 통과할 수 있는 것은 없다」고 적었는데, 두 가지가 틀렸다 — 실행 결과는 **열여섯 검사**였고(규칙 15 · 검사 16), 무엇보다 **글자 크기 Tailwind 프리셋**(`text-sm`·`text-lg`)은 어느 검사도 보지 않았다(7차 페르소나 디자이너 low). 8/27에 그 통로를 행간 ③과 같은 모양으로 닫고(⑰) 숫자를 실행 결과와 맞췄다. 지금은 **열일곱 규칙 · 열여덟 검사**이고, 그중 「모르는 값이 통과할 수 있는」 것은 없다.
    - 세는 규칙 (17종):
      ① 죽은 폭 제한(`max-w-[5~9xx px]`)
      ② **행간 임의값 허용 목록** — 3단(1.3·1.45·1.6) 밖은 전부 실패. 예외 둘(40px 수치 1.05 · /report 가림 문단 1.85)은 `leading-none`과 같은 방식으로 **파일·개수까지** 등재했다.
      ③ 행간 Tailwind 프리셋(`leading-tight|snug|normal|relaxed|loose`) 0건
      ④ **`leading-none` 파일·개수 허용 목록**(단일 글리프 전용 — **9개 파일 10곳**)
      ⑤ **반지름 허용 목록** — `rounded-*`는 토큰 클래스(card·panel·field·chip·full)이거나, 사유·개수까지 등재된 리터럴 아홉 종(바텀시트 22 · 말풍선 복합 둘 · 10 · 9 · 6 · 5 · 2 · 1px)이어야 한다.
      ⑥ 글자 크기 사다리 허용 목록(§9-7)
      ⑦ 뷰포트 브레이크포인트(§9-6, 예외 1곳과 그 개수까지)
      ⑧ **별칭 토큰**(§9-8) — `white` 포함
      ⑨ CSS `font-size`·`line-height` 선언(rem만 · 사다리와 3단 안)
      ⑩ **`text-brand-700`과 색 면의 동거** — 같은 className 문자열 안은 예외 없이 0건(변형 접두 `active:`·`hover:`가 붙은 면도 함께 센다), 같은 파일 안이면 「흰 지면임을 사람이 확인한」 허용 목록에 등재돼 있을 때만 통과(정규식으로는 글자가 그 면 *안*인지 알 수 없기 때문이다 — 홈 `ResumeCard`는 면이 86행, 글자가 107행이었다)
      ⑪ `animate-pulse` 0건(§9-10)
      ⑫ **생 hex `#ffffff`** — 「Tailwind 클래스가 닿지 않는 자리」 넷만 사유와 함께 등재(§9-8)
      ⑬ **SVG `fontSize={N}` 속성** — 같은 사다리를 px로 본다. `text-[Xrem]`과 CSS 선언만 보던 그물의 사각지대였다(§9-13)
      ⑭ **짧은 라벨 액션의 48px 폭** — `min-h-[48px]`를 가진 요소의 라벨 폭을 어림해(글자 크기 × (한글 수 + 0.55 × 그 밖) + 좌우 `px-*`) 48px에 못 미치면 `min-w-[48px]`나 늘어나는 폭(`w-full`·`flex-1` 등)을 요구한다. 3차·5차에 연속으로 샌 자리다(§9-14)
      ⑮ **아이브로 한 벌** — 손수 사본은 문단을 넣을 수 없는 자리(링크·`<summary>` 안 `<span>` · `<dt>` · `<th>`)만 파일·개수로 등재(§9-15). 8/27에 **자간 없는 사본**도 보게 넓혔다 — 자간을 키로 삼는 동안 「12.5px `<p>` 한 줄에 짧은 리터럴」 형태가 그물을 통과했고, 하필 그것이 5차에 이름까지 댄 대표 사례였다
      ⑯ **아이브로 색은 `tone` prop** — `<EyebrowLabel>`의 `className`에 잉크 클래스가 오지 않는다(§9-15)
      ⑰ **글자 크기 프리셋·px·pt 금지** — `text-sm`류 0건 · `text-[Npx]`/`[Npt]` 0건. 행간이 ③으로 닫아 둔 통로의 짝이다
    - ③④⑨⑩⑪은 2026-08-26 1차 신설이고, ②⑤의 뒤집기와 ⑫⑬⑭⑮는 같은 날 2차 신설이며, ⑯⑰과 ⑮의 확장·⑭의 장부 확장은 2026-08-27 3차분이다. 신설할 때마다 **위반을 일부러 심어 모든 경우가 잡히는지, 주석에만 적힌 낱말은 잡히지 않는지**를 확인했다(2차: 양성 17 · 음성 3, 전부 기대대로).
    - **`PENDING_*` 목록**은 「사유가 있어 열어 둔 예외」가 아니라 **아직 안 고친 자리**다. 다른 구역이 소유한 파일이라 그 커밋이 손대지 않은 것들이고, 파일·개수가 못 박혀 있어 늘어나면 실패한다. 고치는 쪽은 실코드를 고친 뒤 목록에서 줄을 지우면 되고, 목록이 비면 그 검사는 예외 없는 규칙이 된다.

12. **하단 탭바 = 아이콘 5종 + 라벨** (2026-08-25 팀장 판정 · 8/26 등재). §3의 「문자 기호만」과 §4.10의 「텍스트 5개 균등 · 이모지·아이콘 없음 · 성장」은 **폐기**다(같은 형식으로 취소선을 그어 두었다 — 표를 그대로 읽는 다음 사람이 방금 확정한 아이콘을 걷어내지 않게).
    - 다섯 칸은 **홈 · 훈련 · 응급 · 보고 · 이력**이다. 다섯째 칸의 라벨은 「성장」이 아니라 **「이력」**이다(2026-08-25 개명 — 「성장」은 감정 설계상 남겨 두었던 이름인데, 그 탭이 실제로 여는 것은 지난 회차 목록이라 이름이 화면과 달랐다).

13. **글자 크기 3단은 화면 전체에 걸린다 — SVG 안도 예외가 아니다** (2026-08-26). 앱의 「글자 크기」(루트 100/112.5/125%)는 토큰이 전부 rem이라 화면이 통째로 비례하는데, `/safety` 근거 확인 흐름도만 폭이 `w-[700px]`이라 그 비례에서 빠져 있었다 — 「아주 크게」를 쓰시는 분에게 **이 다이어그램만 작게** 남는, 앱에서 유일한 타이포 섬이었다(5차 페르소나 디자이너 low). 하필 판정 근거를 보여 주는 화면이라 심사에서 열릴 가능성이 크다.
    - 고친 방법은 폭을 **viewBox와 1:1로 맞춘 rem 한 값**이다 — `45rem`은 기본 루트에서 720px이고 viewBox도 720이라 **좌표 1이 곧 1px**이 된다(예전 700px에서는 0.972배가 곱해져 17이 16.53px로 그려졌다). 루트가 커지면 그림이 통째로 같은 비율로 커지므로, 손으로 놓은 선과 상자의 관계는 한 픽셀도 어긋나지 않는다. 가로 스크롤은 이미 바깥 상자가 맡는다.
    - 그림 안 글자는 SVG `fontSize` 속성이고 **눈금은 화면과 같다** — 15 · 17 · 19px 셋뿐이다(사다리에 없는 20px은 섹션 제목 눈금 19로 내렸다). 게이트 ⑬이 이 속성을 센다.
    - 일반 규칙: **좌표계 위에 손으로 놓은 그림은 폭을 rem으로 적고, viewBox와 같은 수로 맞춘다.** 그러면 안의 숫자를 그대로 사다리로 검사할 수 있다.

14. **48px은 높이만이 아니라 폭이다** (2026-08-26). 터치 타깃 하한 48px은 `TabBar`가 세운 규칙인데, 코드에는 `min-h-[48px]`로만 적혀 있어 **폭이 빠진 자리**가 라운드마다 새로 나왔다 — 3차에 「닫기」 넷, 5차에 `MaskReview`의 「닫기」와 /console의 「빼기」가 같은 방식으로 남았다. 두 번 다 사람이 손으로 세었고 두 번 다 형제 하나를 놓쳤다(5차 페르소나 UI/UX low — 「고치는 단위가 그 줄」).
    - 짧은 라벨은 폭이 저절로 차지 않는다: 13.5px 두 글자(약 27px)에 좌우 `px-2`(16px)를 더해도 43px이다. 세 글자면 56px이라 그냥 넘는다 — 그래서 규칙의 대상은 **짧은 라벨**이다.
    - 적는 방식은 `min-w-[48px] justify-center` 한 벌이다(폭이 부모에 의해 늘어나는 버튼 — `w-full`·`flex-1` — 은 그럴 필요가 없다).
    - 게이트 ⑭가 라벨 폭을 어림해 센다(글자 크기 × (한글 수 + 0.55 × 그 밖) + 좌우 `px-*`). 못 세는 자리는 **세 갈래 전부** 파일·개수로 못 박아 두었다 — ⓐ 클래스가 공용 상수로 빠진 자리 · ⓑ 라벨이 문자열 리터럴 없는 표현식인 자리 · ⓒ 여는 태그 뒤가 곧바로 다른 요소인 자리. **못 세는 자리가 조용히 늘면 그것도 실패한다.** (8/27 교정: 장부가 ⓐ 하나뿐이던 동안 104자리 중 53자리가 아무 기록 없이 지나갔고, 같은 절이 「조용히 늘어나면 알게 한다」고 단언하고 있었다 — 7차 페르소나 UI/UX low.)

15. **아이브로는 한 벌이다 — 12.5px / 700 / +.06em / `ink-muted`** (2026-08-26). 정본은 `components/EyebrowLabel.tsx`다. 실측에서 손수 사본이 컴포넌트와 맞먹었고(사용 46 대 손수 36) 더 나쁘게는 **자간이 두 값으로 갈려 있었다** — `.06em` 19줄 · `.04em` 17줄. 같은 낱말이 같은 흐름의 두 화면에서 다르게 서고, 한 파일이 같은 낱말을 한 번은 컴포넌트로 한 번은 손으로 적는 자리까지 있었다(5차 페르소나 디자이너 med).
    - §2 표의 「+0.05~0.06em」은 **범위**였다. 사다리를 열두 값으로 좁힌 것과 같은 이유로 **.06em 한 값**으로 정한다 — 지각 역치 아래의 차이는 위계를 만들지 못하고 화면 간 편차만 만든다.
    - **색은 `tone` prop으로 고른다**(8/27 교정). 값은 다섯이고 이 목록이 전부다 — `muted`(기본 `ink-muted`) · `brand`(**brand-800**) · `danger`(`danger-ink`) · `ok`(`ok-ink`) · `soft`(`ink-soft`, 「다시 볼 것」처럼 잘못이 아니지만 눈이 가야 하는 목록 위). 여백·레이아웃만 `className`으로 넘긴다.
      - 왜 prop인가: 한동안 「색이 다른 변형은 `className`으로 넘긴다」고 적혀 있었는데, `cx`는 tailwind-merge가 아니라 **이어붙이기**이고 컴포넌트가 기본 잉크를 이미 들고 있어 결과가 `text-ink-muted text-brand-800` 꼴이 됐다. 같은 레이어·같은 명시도라 **생성된 CSS에서 뒤에 나오는 쪽**이 이기는데 Tailwind는 알파벳 순으로 내보내므로 `.text-ink-muted`가 brand·danger보다 뒤에 서고, 6차가 새로 만든 색 변형 여섯 중 **다섯이 무효**였다(7차 페르소나 FE med). 소스 문자열로는 완전히 정상으로 보이는 결함이라 규칙이 아니라 **길 자체**를 막았다. 게이트 ⑯이 그 규율을 지킨다.
      - `brand`가 700이 아니라 800인 것도 규칙이다 — 700은 「흰 지면 위 링크」의 단이라(§9-8) 누를 수 없는 이름표에 서면 색이 뜻을 잃는다. 실제로 /safety 문서 목록의 아이브로 하나만 700이었고 같은 화면의 형제 둘은 800이었다.
    - 남는 예외는 **문단(`<p>`)을 넣을 수 없는 자리**뿐이다 — 링크·`<summary>` 안의 `<span>`, `<dl>`의 `<dt>`, 표의 `<th>`. 그 자리는 같은 값을 인라인으로 적고 **사유를 주석으로 남긴다**. 게이트 ⑮가 파일·개수까지 못 박는다.
