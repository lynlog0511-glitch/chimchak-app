# 침착 문체 가이드 v1 — "한국 서비스 네이티브"

> 2026-08-25 팀장 지시: "AI 특유의 티가 나는 말투를 지우고 한국인 네이티브같이."
> 이 문서가 앱 전 화면 사용자 문구의 단일 기준이다. 시각 언어는 design-guide-v4가, 말은 이 문서가 맡는다.

## 0. 목표 한 줄

읽는 사람이 "누가 썼지?"라고 생각하지 않는 글. 토스·당근 결의 절제 — 짧고, 동사로 끝나고, 필요한 말만.

## 1. AI 티 패턴 — 찾으면 고친다

실제 이 앱에서 뽑은 패턴이다. 각 항목의 ✕는 현재 앱 문장, ○는 고친 방향.

### 1-1. 줄표(—) 남발
문장 중간에 —로 부연을 잇는 버릇. **한 화면에 줄표 문장 1개까지.** 나머지는 마침표로 끊거나 부연을 버린다.
- ✕ "온라인 모드는 켜져 있지만, 지금 서버에 AI 연결이 준비돼 있지 않아 — 외부 AI로는 아무것도 전달되지 않았습니다"
- ○ "지금은 서버에 AI 연결이 없어요. 외부로 나간 말은 없습니다."

### 1-2. 「」 과다
낫표는 **화면에 실제로 있는 버튼·메뉴·화면 이름을 지칭할 때만.** 강조·개념어에는 쓰지 않는다.
- ✕ "「예시 지우기」를 누르시면" → ○ 유지 (버튼 이름)
- ✕ "「왜 이 판정인가요?」 같은 개념 강조" → ○ 낫표 제거하거나 문장 재구성

### 1-3. 이유 부연 강박
모든 문장이 자기 이유를 설명한다("~하기 때문입니다", "~하려는 자리입니다", "~않게 하려고요").
**이유가 곧 사용자에게 필요한 정보일 때만 남긴다.** 설계 의도 해설은 삭제.
- ✕ "시간이 지나도 자동으로 넘어가지 않습니다 — 생각할 시간을 드리려는 것입니다"
- ○ "시간이 지나도 자동으로 넘어가지 않아요. 천천히 생각하셔도 됩니다."

### 1-4. 명사문 종결
"~하는 자리입니다 / 장치입니다 / 문법입니다 / 구조입니다" — 설계 문서 말투다. 동사로 끝낸다.
- ✕ "정답을 맞히는 자리가 아니라, 말이 나오게 만드는 자리입니다"
- ○ (시그니처 카피는 예외 — §3) 일반 문장은 "정답을 맞히지 않아도 됩니다. 말이 나오면 됩니다."

### 1-5. 번역투·문어투
- "~하게 두었습니다 / 적어 두었습니다" → "~했어요 / 적었습니다"
- "그 사실을 그대로 적었습니다" → (문장 삭제 — 적은 내용이 곧 증거다)
- "~로 답합니다 / ~를 폅니다 / ~가 맡습니다"의 의인화 반복 → 줄인다
- "말씀하신 발화 원문" → "하신 말씀 원문" ("발화"는 내부 용어)

### 1-6. 강조 부사 반복
"그대로 · 전부 · 직접 · 실제로 · 스스로"가 한 문단에 두 번 이상이면 하나만 남긴다.

### 1-7. 병렬 3연타
"판정도 게이지도 기록도 남기지 않고" 류의 리듬 과시 → 필요한 항목만. 가운뎃점 나열은 3항까지.

### 1-8. 접속 부사 사슬
"다만 / 단 / 그래서 / 그런데"로 문장을 계속 잇는 버릇 → 문단당 1회.

## 2. 존댓말 규칙

| 자리 | 문체 | 예 |
|---|---|---|
| 안내·고지·법적 문구 | 합니다체 | "발화 원문은 저장하지 않습니다." |
| 격려·대화 유도·빈 화면 | 해요체 | "먼저 말을 건네 보세요." |
| 버튼·라벨 | 명사형 또는 "~하기" | "훈련 시작하기", "예시 지우기" |
| 경고·금지 | 합니다체 + 단문 | "실제 인물의 정보는 적지 마세요." |

한 문단 안에서 합니다체·해요체를 섞지 않는다. 화면 단위로는 섞여도 된다(고지는 합니다, 격려는 해요).

## 3. 건드리지 않는 것

1. **동결 문구**: 고정 고지(INLINE_DISCLAIMER_TEXT) 원문 · 가상 인물 고지 · 119 캡션 · "판정: … (AI 아님)" 형식 · 검증 계단 수치와 result/hypothesis 원문 · 확인서 법적 경계 문구·발급번호·CSV 구조 · 시행일 칩
2. **동의 문구**: FREE_CONSENT_LINES · ONLINE_COACHING_NOTICE · /legal의 법적 실질 문장 — 법령 대조를 거친 문안이라 리듬만 다듬고 정보는 한 글자도 빼지 않는다. 자신 없으면 그대로 둔다.
3. **검수 데이터**: src/data/scenarios/ 대사·나레이션 전부, protocols.ts 응급 문구 — 감수 계보가 걸려 있다.
4. **시그니처 카피**: "정답을 맞히는 시험이 아니라, 말이 나오게 만드는 연습입니다." — 홈·브리핑의 이 문장은 제품 정체성이라 유지.
5. **확정 어휘**: 가명처리 · 공식 문서 목록 · 상황 훈련 · 자유 연습 · 체험용 예시 · 응급 음성 안내 · AI/외부 AI — 이름은 바꾸지 않는다(문장만 다듬는다).

## 4. 판별법 — 헷갈리면 이 질문

1. 이 문장을 소리 내 읽으면 사람 말 같은가?
2. 이 부연을 지우면 사용자가 잘못 행동하게 되는가? (아니라면 지운다)
3. 이 문장은 사용자에게 말하는가, 심사위원에게 말하는가?
