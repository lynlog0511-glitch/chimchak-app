**강점**
- 모달 문법이 앱 전체에서 하나로 통일됨 — `useModalDismiss`(useModalDismiss.ts:29-72)가 마운트 초점·Esc·Tab 트랩·여닫은 뒤 초점 복귀를 한 벌로 제공하고, 종료 확인(TrainSession.tsx:52-98)·⚑CF 바텀시트(CriticalInterrupt.tsx:37)·규칙 시연 시트가 모두 이 훅을 씀. 여는 쪽 화면이 배경 세션에 `aria-hidden`을 거는 규칙(TrainSession.tsx:463·474)까지 짝을 맞춤
- 글자 크기 설정이 실효 — 실측으로 루트 font-size 16/18/20px가 실제 적용되고(rootFont "20px"), 대사 말풍선이 17px→21.25px로 비례. 컴포저 상한도 스케일별로 45/42/40dvh로 내려 로그 가시 면적이 385→401→409px로 오히려 늘어남(접근성 설정이 읽을 면적을 뺏는 역전을 실제로 막아 냄)
- 턴·단계 전환 초점 관리가 일관됨 — 세션은 새 CUE 지시문 h2로 `focus({preventScroll:true})`(CueResponder.tsx:168-174), /report는 각 단계 h2로 이동 + 확정 직후 「확정했습니다」로 이동(ReportWizard.tsx:74-82). 매 턴 스킵링크부터 Tab을 다시 밟는 일이 없음
- /report 2·3단계 전진 CTA가 실제로 화면 안에 고정됨 — 390×844 실측에서 「확인으로 넘어가기」 y=661, 「이대로 확정하기」 y=661로 탭바(783) 위에 핀 고정. StickyCtaBar가 「마지막 자식이면 붙지 않는다」는 sticky 함정까지 문서화하고 PrivacyPath를 아래에 남겨 해결(StickyCtaBar.tsx:22-45)
- 응급 재생기는 팔 길이 사용을 전제로 실제로 접힘 위에 다 들어옴 — /emergency/p-01 390×844 실측에서 sticky 상단(119 버튼 포함) 160px, 29px 자막 206~332, 이전/멈춤/다음 429~481. 세션 안 L3의 sticky 119 바도 고정값이 아니라 실측 `--session-head-h`를 써서 헤더와 겹치지 않음(ProtocolInline.tsx:88-89)
- 빈 상태가 막다른 길이 아님 — /history 무기록 상태에서도 「다음엔 이 장면」 추천, 유형별 4칸, 「첫 훈련 시작하기 ›」·「음성 보고하러 가기 ›」·이수 확인서 진입이 모두 살아 있음(렌더 실측). 브리핑은 844 안에 한 화면으로 들어오고 CTA가 y=379.5
- 이탈·재진입 경로가 촘촘함 — 세션 헤더의 ‹(브리핑 복귀)·종료 확인 모달·체크포인트 「이어서 하기/처음부터 다시 시작」이 실제로 동작(리로드 후 두 버튼이 뜨는 것을 실측). 시연 프리셋 세션은 체크포인트·성장 기록을 오염시키지 않도록 저장을 건너뜀(TrainSession.tsx:279-284·298-301)

**증거**: 390×844 실측(/train/chk-a01 첫 턴). 18px(크게): 도크 354px, 내부 감춤 97px, 마이크·「직접 입력…」 행 bottom 855 > 도크 내부 bottom 844 → 보이지 않음. 20px(아주 크게): 도크 338px(=40dvh 상한), 내부 감춤 152px, 제안 버튼 3개가 632~838을 다 차지하고 「직접 입력…」 top 850·마이크 top 854·「규칙 엔진 시험해 보기」 top 920 전부 접힘 아래. 상한은 CueResponder.tsx:54-58 `DOCK_MAX_H`, 내부 스크롤은 CueResponder.tsx:502. 표준(16px)에서는 감춤이 27px뿐이라 이 역전은 접근성 설정을 켠 사용자에게만 발생. 게다가 가이드가 그림자·그라데이션을 금지해(globals.css:141-147) 「여기 더 있다」는 어포던스가 0.

### [major · 작업량 중] 한 턴 증분이 대화 가시 띠의 1.3~1.8배인데, 유일한 회수 장치인 꼬리 앵커가 자기취소 루프에 걸림

**증거**: 실측: 표준 16px에서 헤더 79px + 도크 379.8px(=45dvh 상한) → 대화 가시 띠 385px. 그런데 한 턴이 붙이는 내용은 문서 높이 증가로 볼 때 496px(턴0: 844→1340)·711px(턴1: 1340→2051)·878px(턴4)이라 어르신 대사 아래의 코칭 카드는 매 턴 화면 밖. 회수 장치는 「이어지는 코칭 보기 ↓」 앵커 하나인데(TrainSession.tsx:608-618), 그 상태를 만드는 효과가 DialogueLog.tsx:348-376이고 ① deps에 `bottomInset`이 있고 ② cleanup이 `onTailOffscreen(false)`를 부릅니다. 앵커는 도크 **안**에 렌더되므로(TrainSession.tsx:600) 앵커가 뜨는 순간 도크 높이가 바뀌고(실측 368px → 상한 379.8px로 클램프) → `dockHeight` 갱신(TrainSession.tsx:150-173) → `bottomInset` 변경 → 효과 재실행 → cleanup이 방금 켠 상태를 끕니다. 실제로 로그 꼬리가 확실히 접힘 아래(sentinel y≈1329, 뷰포트 844)인 상태에서 500ms 간격 6회(총 3초) 샘플링했으나 앵커 버튼은 DOM에 한 번도 존재하지 않았습니다.

**제안**: 앵커를 도크 밖(로그 컨테이너의 fixed 오버레이)으로 옮겨 `bottomInset`에 영향을 주지 않게 하거나, IntersectionObserver의 rootMargin을 상태에 따라 변하지 않는 고정값(도크 상한 45dvh)으로 고정해 effect의 deps에서 `bottomInset`을 빼세요. cleanup의 `onTailOffscreen(false)`는 언마운트 시에만 의미가 있으므로 ref 가드로 감싸면 됩니다. 근본적으로는 코칭 카드를 대사 아래가 아니라 도크 상단의 접힘 한 줄(「이번 응답 코칭 ⌄」)로 올리는 편이 385px 띠에 맞습니다.

### [minor · 작업량 소] 완주 직후 엔딩 패널의 ✓ 마크와 「훈련 마침」이 sticky 헤더 밑에 깔림

### [minor · 작업량 소] SettingsMenu만 앱의 모달 문법에서 예외 — 초점 이동·Esc 복귀 규칙이 다름
