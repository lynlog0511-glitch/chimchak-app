## 2. 시나리오 표준 스키마

> 모든 시나리오는 아래 스키마를 준수한다. 시나리오는 **문서가 아니라 데이터**이며, 이 스키마를 채우면 개발자·현직 감수자·심사위원이 동일한 대상을 본다.

### 2.1 필수 구성 요소 (지침 §2 대응)

| 지침 요구사항 | 스키마 필드 | 강제 여부 |
|---|---|---|
| 명확한 학습/평가 목표 | `learning_objectives[]` (각 LO는 루브릭 항목 ID 2개 이상과 연결) | 필수 |
| 현실적 배경 및 맥락 | `context` (시각·장소·계절·기온), `personas[]` (역할·이력·상태) | 필수 |
| 문제의 심각성 | `severity` (1~5) + `escalation_curve` | 필수 |
| 제약 조건 | `constraints[]` (시간·인력·장비·연락 가능성·법적 금지) 최소 3개 | 필수 |
| 분기 시나리오 | `states[]` + `branches[]` (응답유형 → 상태전이 → AI 반응) | 필수 |
| 돌발 변수/트리거 | `triggers[]` (발동조건·목적·측정 루브릭 ID) 최소 2개 | 필수 |
| 상호작용 지점(CUE) | `cues[]` (발화/행동 요구, 대기시간, 폴백) | 필수 |
| — (침착 추가) | `scoring_hooks[]` (턴별 즉시 채점 시점), `endings[]`, `fallbacks[]`, `source_docs[]` | 필수 |

### 2.2 스키마 정의 (YAML)

```yaml
scenario:
  id: CHK-A01                    # CHK-{유형코드}{일련}
  version: "1.0-alpha"
  type: BPSD                     # BPSD | EMERGENCY | CONFLICT | RISK_JUDGMENT
  level: 1                       # 1 초급 | 2 중급 | 3 고급
  est_duration_sec: 240
  turns_expected: 6              # AI 발화 기준
  generation_tier: [L1, L2]      # 이 시나리오가 사용하는 생성 계층
  mvp_features: [F1, F3]         # F1 시뮬레이터 / F2 음성가이드 / F3 기록코칭

  learning_objectives:
    - id: LO-1
      statement: "..."
      rubric_items: [RE-01, RE-02]

  personas:
    - role: care_recipient | guardian | dispatcher | learner
      name: "박 어르신"           # 가상 인물. 실존 인물·기관과 무관
      profile: {...}

  context: {time, place, season, temperature, preceding_events}
  constraints: [...]             # 최소 3개
  severity: 3
  escalation_curve: {var: agitation, range: [0,5], start: 2}

  states:  [S0, S1, S2, S3, S4]
  cues:    [{id, prompt, wait_sec, fallback}]
  branches:[{cue, response_type, delta, ai_reaction, rubric_hit}]
  triggers:[{id, condition, effect, purpose, rubric_target}]
  endings: [{id, condition, judgment}]
  fallbacks:[{failure_mode, behavior}]
  scoring_hooks: [{after_cue, items: [...]}]
  source_docs: [DOC-LAW-001, DOC-GUIDE-003, ...]
  review:  {reviewer, date, decisions: [...]}
```

### 2.3 생성 계층과 시나리오 요소의 대응 (기획서 p.6 3계층 통제 구현)

| 계층 | 시나리오 내 담당 요소 | 파라미터 | 이탈 시 동작 |
|---|---|---|---|
| **L1 생성 허용** | 어르신·보호자의 **역할 발화**(대사 생성, 감정 표현, 되받아치기) | 온도 0.7 · 페르소나 프롬프트 + 턴별 앵커 대사 고정 | 앵커 이탈·금지어 탐지 → 재생성 1회 → 실패 시 템플릿 고정 대사 |
| **L2 제약 생성** | **채점·피드백·근거 인용** | 온도 0.2 · 벡터검색 top-k=4 · 검색 문서만 컨텍스트 주입 · 출력 후검증 | 근거 미검색 → 미응답 + "공식 지침에서 근거를 찾지 못했습니다. 담당 간호사·기관에 문의하세요" |
| **L3 생성 금지** | **응급 음성 가이드 프로토콜**(B02의 P-02) | LLM 호출 없음. 의도 라벨 → 프로토콜 ID 룩업 → 사전 검수 고정 스크립트 재생 | 오프라인 캐시 재생 + 119 버튼 확대 |

> **설계 의도:** 할루시네이션은 "LLM을 잘 달래서" 줄이는 것이 아니라, **위험도가 높은 구간에서 LLM을 아예 빼는 구조**로 줄인다. 알파 3종은 이 세 계층을 각각 최소 1회 이상 실제로 통과하도록 편성했다.

### 2.4 알파 3종 편성 근거

| 시나리오 | 유형 | 난이도 | 계층 | MVP 기능 | 편성 근거 (증거 강도 순) |
|---|---|---|---|---|---|
| CHK-A01 배회·귀가 요구 | ① BPSD | 초급 | L1+L2 | F1, F3 | 치매 교육요구도 '행동문제' 4.09/5로 1위(하은호·조진영, 2015) + 현직 인터뷰 N-4 원문 사례 |
| CHK-B02 식사 중 사레·질식 | ② 응급 | 중급 | L1+L2+**L3** | F1, **F2**, F3 | 요양보호사 47.2% 응급상황 경험 · 96.9%가 응급훈련 희망(김순옥·김수연, 2018) + 인터뷰 N-8 "손이 떨려 화면 터치할 여유조차 없다" |
| CHK-C01 보호자 업무 외 요구·폭언 | ③ 갈등 | 중급 | L1+L2 | F1, F3 | **현직 인터뷰 요청 1순위**(기획서 p.3). 국내외 인접 서비스 12종 중 제공 사례 확인되지 않음 → 차별점 실연 지점 |

**알파 제외 결정:** 유형④(낙상·이승 위험 판단)는 현직 인터뷰에서 체력 한계 사례로 가장 강하게 언급된 영역이나, 동작 교정으로 오인될 위험이 알파 단계에서 통제 불가하다고 판단하여 **베타(8월 중순)로 이연**한다. 이연 사유와 대체 설계는 §6 감수 추적표 R-09 참조.

## 3.1 CHK-A01 「현관 앞, 집에 가야 해요」

> **유형** ① 치매 행동심리증상(BPSD) · **난이도** 초급 · **소요** 약 4분 · **계층** L1+L2 · **기능** F1 시뮬레이터 + F3 기록코칭

### A. 학습·평가 목표

| ID | 학습목표 | 연결 루브릭 항목 | 측정 방식 |

### 4.2 4점 척도 공통 정의

| 점수 | 명칭 | 공통 정의 | 사용자 화면 |
|---|---|---|---|
| **4** | 우수 | 기대 행동을 수행했고, **왜 그렇게 했는지의 근거·순서까지** 드러났다 | 🟢 충족 + 강화 문구 |
| **3** | 충족 | 기대 행동을 수행했다 | 🟢 충족 |
| **2** | 부분 | 시도했으나 시점이 늦거나 내용이 불완전하다 | ⚪ 코칭 문장 1개 |
| **1** | 미흡 | 수행하지 않았거나 반대 방향으로 행동했다 | ⚪ 코칭 문장 1개 + 근거 출처 칩 |

> **점수는 사용자에게 표시하지 않는다.** 기획서 p.7 고령 사용자 접근성 정책("점수·등급 미표시, 충족 원칙만 초록 체크")에 따라 화면은 🟢/⚪ 2단계와 코칭 문장, 근거 출처 칩만 노출한다. 4점 척도는 **내부 채점·훈련 이력·현직 교차 채점 신뢰도(κ) 산출 전용**이다.


**후검증 규칙** — 아래 중 하나라도 위반 시 응답 폐기 후 폴백

**확장 시 추가 작업량** — 시나리오 1종당: 스크립트 작성 4h + 현직 감수 1h + 근거 문서 매핑 1h + 구현 2h = **약 8h**. 루브릭 30항목은 재사용하므로 확장 원가가 선형이 아니라 **체감**한다.

### 9.2 타 직군 이식 규칙 (대중적 확장 가능성)

침착의 시나리오 스키마(§2.2)는 **도메인 독립적**이다. 이식 시 교체하는 것은 세 가지뿐이다.

| 교체 대상 | 요양보호사(현재) | 장애인활동지원사 | 간병인 | 보육교사 |
|---|---|---|---|---|
| **① 근거 문서 세트** | 노인복지법·장기요양 고시·중앙치매센터 | 장애인활동지원법·활동지원 급여 고시 | 의료기관 간병 지침 | 영유아보육법·표준보육과정 |
| **② 시나리오 유형 4종** | BPSD·응급·갈등·위험판단 | 의사소통·이동지원·갈등·응급 | 체위·감염관리·갈등·응급 | 안전사고·행동지도·학부모 갈등·응급 |
| **③ 페르소나·대사** | 어르신·보호자 | 이용자·가족 | 환자·보호자 | 영유아·학부모 |

**재사용되는 것** — 루브릭 4대 영역 구조, 4점 척도 앵커 문법, ⚑CF 판정선 개념, 3계층 생성통제(L1/L2/L3), 채점 엔진, 3초 예산 구조, 폴백 매트릭스.
→ 매뉴얼 기반 대인 서비스 직군이면 **시나리오 DB와 근거 문서만 교체해 이식 가능**하다.

### 9.3 훈련 이력의 다음 단계 (기획서 p.10 3단계 연결)

채점 출력 스키마에는 이미 아래 필드가 예약되어 있다. 알파에서는 저장만 하고 노출하지 않는다.

```json
"competency_profile": {
  "type_coverage":   {"BPSD": 3, "EMERGENCY": 2, "CONFLICT": 1, "RISK": 0},
  "cf_free_streak":  7,
  "domain_scores":   {"SA": 3.2, "CO": 3.8, "RE": 2.9, "CL": 3.4},
  "verified_by":     null,
  "issued_at":       null
}
```

> 현직 인터뷰 N-10의 요구 — "경력 연수 외에는 이 사람이 현장에서 얼마나 위기 대처를 잘하는지 객관적으로 증명할 길이 전혀 없어요" — 에 대응하는 설계이며, **2028년 역량 프로필 단계에서 사용자 동의를 전제로만** 발급한다.
